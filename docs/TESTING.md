# 维修资金管理系统（wxzj）测试文档

> 本文档覆盖系统功能测试、业务场景测试、接口测试、异常与边界测试，用于验收与回归。
> 环境：后端 `http://localhost:8080`（H2 演示库），前端 `http://localhost:5173`。
> 默认账号：admin / property / committee / owner，密码分别为 `xxx123`。

## 1. 测试准备

### 1.1 环境启动

```bash
# 后端
cd backend && mvn spring-boot:run        # 启动时自动建表 + 初始化演示数据
# 前端
cd frontend && npm install && npm run dev
```

### 1.2 数据基线（初始化后）

- 小区：阳光花园(1)、幸福里小区(2)
- 房屋：阳光花园 6 套、幸福里 4 套，共 10 套，均已开户
- 缴存标准：阳光花园 80 元/㎡、幸福里 100 元/㎡
- 流程定义：USE（业委会审核→主管部门审批）、REFUND（物业核对→主管部门审批）
- 业主李女士（owner 账号）持有幸福里 A-101（房屋 id=7，面积 110 ㎡）

### 1.3 测试口径

- 金额核对规则：`应缴 = 面积 × 标准单价`；分摊到户 = `总金额 × 户面积 / 涉及面积合计`（四舍五入到分）。
- 余额一致性：账户 `balance = totalDeposit - totalUsed - totalRefund`；每笔资金变动必须生成对应流水。

## 3. 端到端业务场景

### 场景 A：业主缴存 → 正常

1. admin 登录 → 基础数据选择房屋 → 缴存登记（待缴）
2. 物业/管理员「到账确认」→ 账户余额增加、生成缴存流水
3. 综合查询核对：`余额 = 缴存额`，流水方向 IN

### 场景 B：维修资金使用 → 审批通过并拨付

1. 物业提交使用申请（多房屋分摊）→ 提交审批
2. 业委会节点 PASS → 主管部门节点 PASS → 状态 APPROVED
3. 管理员拨付 → 各户余额扣减、生成使用流水、状态 PAID
4. 校验：`各户扣减合计 = 申请总额`；`账户余额 = 缴存 - 使用`

### 场景 C：维修资金使用 → 驳回

1. 物业提交 → 业委会 REJECT
2. 流程 TERMINATED、状态 REJECTED、余额不变、无使用流水

### 场景 D：退款 → 审批通过并退款

1. 业主对本人账户发起退款（≤ 余额）
2. 物业核对 PASS → 主管部门 PASS → 状态 APPROVED
3. 管理员办理退款 → 余额扣减、生成退款流水、状态 REFUNDED
4. 校验：`账户余额 = 原余额 - 退款额`

### 场景 E：业主数据隔离

1. owner 登录 → 基础数据仅见本人房屋、账户仅本人、流水仅本人
2. owner 尝试以他人 accountId 发起退款 → 拒绝

### 场景 F：多笔资金混合后的一致性

1. 多次缴存 + 一次使用拨付 + 一次退款后
2. 校验每户：`balance = totalDeposit - totalUsed - totalRefund`
3. 校验统计合计与明细一致

## 4. 接口测试要点（重点校验点）

| 接口 | 重点校验 |
| --- | --- |
| POST /api/auth/login | 401/400 分支、token 有效性 |

## 5. 异常与边界测试

| 类别 | 用例 |
| --- | --- |
| 金额边界 | 面积/单价为 0 或负；总金额为 0；退款金额为 0/负数 |
| 空值 | 必填字段缺失（houseId/communityId/title/amount 等）→ 400 参数校验 |
| 非法参数 | 不存在的 ID（房屋/账户/标准/单据）→ 明确报错，不抛 500 |
| 状态非法跳转 | 草稿直接拨付、待缴直接退款、未审批直接完结等 → 拦截 |
| 流程非法操作 | 已结束流程再审批；非当前节点角色审批；无流程节点配置 |
| 数据一致性 | 任意资金操作后 余额=累计缴存-累计使用-累计退款 恒成立 |
| 并发 | 同一缴存单并发确认、同一申请并发拨付 → 数据库锁/唯一键兜底，不产生重复流水 |
| 唯一性 | flow_no/order_no/apply_no/refund_no 不重复（含同毫秒批量插入） |
